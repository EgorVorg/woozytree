# WoozyTree — дизайн-документ

Клон WizTree (https://diskanalyzer.com/) для Windows: программа показывает, что занимает место на диске. Дата: 2026-11-21.

## 1. Зачем это

Сделать «то же самое, что WizTree», но с другим дизайном: тёмная тема, современный интерфейс на shadcn/ui вместо окон в стиле 2000-х. Функциональность — полный паритет с оригиналом, внешность — новая.

Проект учебный: человек учится вайбкодингу. Поэтому два требования важны наравне с функциями:

- код должен быть простым и читаемым (понятные имена, никаких «хитрых» решений в ущерб ясности);
- ход работы объясняется простым языком, понятным даже тому, кто слабо разбирается в программировании.

## 2. Как устроен оригинал (референс)

WizTree сканирует диск и показывает:

- **treemap** («карту занятости»): прямоугольники, где размер прямоугольника = размер файла или папки. Видно, кто съел место;
- **дерево папок** и **список файлов** с колонками: размер на диске, фактический размер, процент от родителя, дата изменения, количество файлов и папок;
- **группировку по типам файлов** (по расширениям) — тоже с treemap;
- **поиск и фильтры** по имени, размеру, дате;
- **удаление** файлов, открытие файла, «показать в проводнике», копирование пути;
- **экспорт списка в CSV**;
- корректный учёт **жёстких ссылок** (один файл, торчащий под несколькими именами, не задваивает размеры).

Главное в WizTree не картинка, а **скорость**. Пояснение простыми словами: файловая система NTFS (стандартная у Windows) ведёт на диске большое «оглавление» — таблицу MFT (Master File Table) — где записаны все файлы сразу. Обычные программы «ходят» по каждой папке и потому ждут минуты. WizTree читает сразу всё оглавление — и получает те же данные за секунды.

## 3. Цели

1. Полный функциональный паритет с WizTree для Windows (список функций — в разделе 6).
2. Скорость оригинала: NTFS-диски — через чтение MFT; всё прочее — быстрым обходом папок (у оригинала ровно так же).

   Измеримый ориентир (моё решение по итогам ревью): типовой компьютер Windows 10/11, диск ~1 ТБ с миллионом-двумя файлов. Полное сканирование NTFS — **единицы секунд**, сравнимо с WizTree на этом же компьютере; первые данные на экране — **в первую секунду** сканирования; интерфейс во время сканирования **не подвисает**. Сначала делаем простой и понятный код, замеряем, и только если замер проигрывает — оптимизируем узкие места. Режим обхода папок (не-NTFS, сеть) жёсткого порога не имеет: он должен работать и показывать прогресс.
3. Новый дизайн: тёмная тема из коробки, компоненты shadcn/ui с пресетом `b6ZR0yFgO`, тёмная карта занятости.
4. Понятный код и объяснения простым языком — это учебный проект.

## 4. Не делаем (non-goals)

- macOS и Linux — только Windows (решено заказчиком).
- Командная строка и параметры запуска.
- Мультиязычность — интерфейс на русском (моё решение, легко поменять, если скажешь «нужен английский»).
- Установщик, портативная сборка, автообновление, проверка обновлений.
- Всё, что связано с лицензиями оригинала (Supporter Code и т.п.).

## 5. Антицели (что будет провалом, даже если «работает»)

- Сканирование заметно медленнее оригинала — тогда теряется главный смысл.
- Случайная потеря данных при удалении: удаляем только то, что пользователь явно попросил; по умолчанию — в корзину, «навсегда» — только с подтверждением.
- Непонятная структура кода: «умные» решения в ущерб читаемости не приветствуются.

## 6. Функции (паритет с оригиналом)

1. Сканирование: выбор диска (одного или всех), сканирование отдельной папки, повторное сканирование.
2. Treemap диска/папки: подсказка при наведении, клик — «зум» внутрь папки, возврат назад.
3. Дерево папок + таблица файлов с колонками: имя, размер на диске, фактический размер, % от родителя, дата изменения, число файлов/папок. Сортировка по любой колонке.
4. Режим «Типы файлов»: группировка по расширениям + treemap по типам.
5. Поиск/фильтры: по имени, размеру, дате изменения.
6. Действия над файлами: удалить (в корзину / навсегда с подтверждением), открыть, показать в проводнике, скопировать путь.
7. Экспорт списка файлов в CSV.
8. Настройки отображения: размер на диске или фактический, что показывать на карте (файлы/папки), порог «не показывать мелочь».
9. Жёсткие ссылки не задваивают размер (моё решение по итогам ревью): файл засчитывается один раз — в ту папку, где его ссылка встретилась первой; остальные ссылки видны в списках с пометкой «жёсткая ссылка» и 0 байт в итогах. Общий итог по диску совпадает с занятым местом, которое показывает Windows.
10. Сканирование идёт «вживую»: прогресс виден, карта заполняется по мере поступления данных — как в оригинале.

## 7. Ограничения

- Windows. Главный сценарий — NTFS.
- Чтение MFT требует прямого доступа к диску: приложение запускается **с правами администратора** (Windows сам спросит разрешение при старте).
- Диски не-NTFS (FAT32/exFAT), сетевые диски и отдельные папки — обычный обход папок (так же делает оригинал; это не быстрый режим, но он работает везде).
- Стек (задан заказчиком): **Tauri 2 + Rust** — ядро и оболочка; **React + TanStack** — интерфейс; **shadcn/ui** с пресетом `b6ZR0yFgO`, тёмная тема.

## 8. Варианты сборки (как думали)

**A. Windows-first, чтение MFT напрямую — ВЫБРАН.** Rust читает таблицу MFT NTFS-тома напрямую: индекс диска в миллионы файлов за секунды. Запасной режим — обход папок для не-NTFS, сетевых дисков и отдельных папок. Это буквально устройство оригинала, включая его запасной режим. Минус: самый деликатный код проекта (сырой доступ к диску, разбор записей MFT), и главный режим привязан к Windows + NTFS.

**B. Обход папок везде.** Один простой код, но диск в терабайт сканируется десятки секунд вместо нескольких. Отброшен: скорость — причина существования WizTree; без неё это уже не клон.

**C. Гибрид с кроссплатформенными ускорителями.** MFT на Windows и «что получится» на других ОС. Отброшен: вне Windows ускориться почти негде, получается вариант B с лишней работой. Кроссплатформенность может прийти потом отдельной задачей.

## 9. Как это устроено (принятые решения)

**Общая схема.** Приложение Tauri = два мира. **Rust** («мозг»): сканирует диск, строит индекс файлов в памяти, считает раскладку treemap, удаляет файлы, пишет CSV. **React** («лицо»): рисует интерфейс, показывает данные, собирает клики пользователя. Они общаются через встроенный механизм Tauri: команды (фронт просит что-то сделать) и события (бэкенд порциями отдаёт данные).

**Сканирование.** Для NTFS читаем MFT напрямую (сырое чтение тома: находим саму таблицу на диске и разбираем её записи — там имена, размеры, связи «файл → папка»). Первым этапом — короткий пробный шаг (спайк): проверить на реальном диске, каким способом это надёжнее делать (разбор MFT руками против готовых крейтов) и подтвердить права доступа. Для всего прочего — обычный обход папок.

**Живая выдача данных.** По мере сканирования бэкенд отправляет данные порциями (батчами) через события Tauri. Интерфейс «заполняется» в реальном времени: прогресс-бар, растущая карта.

**Treemap.** Раскладку (классический алгоритм squarified: как разбить прямоугольник на плитки пропорционально размерам) считает Rust — он быстрый и это один общий язык для всех данных. На фронт уходят готовые прямоугольники (координаты + имя + размер), фронт рисует их на **canvas** (нарисовать десятки тысяч прямоугольников обычными элементами страницы нельзя — браузер не вытянет). Наведение, клик и зум — поверх canvas.

**Список файлов.** Виртуализация через TanStack Virtual: на экране рисуются только видимые строки, а не миллион. Сортировка и колонки — TanStack Table.

**Удаление.** По умолчанию — в корзину Windows (можно вернуть). «Навсегда» — только после явного подтверждения.

**Поиск и фильтры.** Индекс файлов целиком лежит в памяти, поэтому фильтрация — мгновенная, без повторного сканирования.

**Интерфейс.** Тот же экран, что у оригинала, но тёмный и на shadcn/ui:

```
┌────────────────────────────────────────────────────────────┐
│ WoozyTree   [Диск (C:) ▾] [Сканировать]  [Карта][Типы][Поиск] │
├────────────────────────────────────────────────────────────┤
│ ▼ C:\                        │   КАРТА ЗАНЯТОСТИ (treemap)  │
│   ▼ Users                    │   ┌─────────┬──────┬───┐    │
│     ▼ georg                   │   │ Users   │ Win- │Pr.│    │
│   ▸ Windows                   │   │         │ dows │F. │    │
│   ▸ Program Files             │   └─────────┴──────┴───┘    │
├────────────────────────────────────────────────────────────┤
│ Файлы:  имя | размер | на диске | % | изменён              │
│         ...прокручиваемый список, тысячи строк...           │
└────────────────────────────────────────────────────────────┘
```

**Проверки на этапах (моё решение по итогам ревью).** Автотесты — на чистую логику: разбор записей MFT, раскладка treemap, фильтры и поиск, запись CSV. Разбор MFT тестируем на заранее снятых «слепках» записей; вспомогательная маленькая утилита для съёмки таких слепков с реального диска — часть проекта. Удаление файлов проверяем **только** на специально созданной тестовой папке с мусорными файлами — никогда на реальных данных (это антицель из раздела 5). В конце каждого этапа — короткая ручная проверка на реальном компьютере.

**Сопровождение для обучения.** Каждое действие объясняется простым языком. В коде — понятные имена и короткие комментарии там, где логика неочевидна. Работа идёт этапами: после каждого этапа — простое объяснение, что сделано и что получилось; на больших вехах (готов сканер, готова карта, готов список файлов) — пауза, чтобы посмотреть результат. Если скажешь «без пауз» — прохожу всё до конца и объясняю по ходу.

## 10. Что решает разработчик (оставлено на усмотрение сборщика)

- Выбор конкретных крейтов Rust (парсинг MFT, работа с корзиной Windows, получение информации о файлах).
- Детали разбора записей MFT: симлинки, junctions, репарс-поинты, поведение при «битых» записях.
- Размер батчей и точный формат обмена данными между Rust и фронтом.
- Структура модулей Rust и файлов фронтенда.
- Точная кастомизация тёмной темы shadcn (в рамках пресета `b6ZR0yFgO`).
